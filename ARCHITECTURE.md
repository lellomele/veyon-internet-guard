## Components and command flow

`InternetGuardPlugin` provides the Master toolbar toggle and selected-computer
actions. Commands travel through Veyon's authenticated feature mechanism.
The student-side server invokes `WindowsFirewall`, which creates/removes
named Windows Firewall rules using `INetFwPolicy2`/`INetFwRule`.
The current backend does not launch command-line tools. Errors retain HRESULTs;
rule removal handles duplicate/missing owned entries.

The toggle UUID is `a4b3c2d1-e5f6-7890-abcd-ef1234567890`; its feature UID and
`uid()` must agree. Metadata IID `io.veyon.Veyon.Plugins.InternetGuard` is a
separate stable identifier. Action sub-features have distinct constant UUIDs.
`VeyonCompat.h` centralizes API includes, target-version macros and command decoding.

## Firewall behaviour

| Owned rule | Transport/port |
|---|---|
| VeyonIG_BlockHTTP | TCP 80 |
| VeyonIG_BlockHTTPS | TCP 443 |
| VeyonIG_BlockDNS_UDP | UDP 53 |
| VeyonIG_BlockDNS_TCP | TCP 53 |
| VeyonIG_BlockQUIC | UDP 443 |
| VeyonIG_BlockDoT_TCP | TCP 853 |
| VeyonIG_BlockDoT_UDP | UDP 853 |
| VeyonIG_BlockProxy | TCP 8080,8443,3128 |

Rules persist until removal. Apply removes owned duplicates before recreating;
release also cleans the legacy owned name `VeyonIG_AllowLAN`.
Block precedence means a LAN allow rule cannot exempt the same blocked ports.
The plugin does not implement hostname/SNI filtering or modify the hosts file.
Port-based blocking is not a general network-security boundary: validate existing
flows, other ports/protocols and local policy in the actual deployment.
Veyon's control ports are not targeted.

## Binary compatibility

Source compatibility does not establish binary ABI compatibility.
Use headers and an import library matching the intended Veyon core, the correct
Qt major/minor and a compatible MinGW toolchain. Do not mix DLLs from other builds.

| Distribution | Headers/import target | Qt/toolchain reference |
|---|---|---|
| Veyon 4.7.5–4.8.x | core 4.7.5 | Qt 5.12, MinGW g++ 7.3 |
| Veyon 4.9.0–4.10.x | core 4.9.0 | Qt 6.7, MinGW 13.1.0 |

A plugin Qt minor newer than the host may be rejected.
Inspect the host's Qt DLL version and the built plugin's Qt version tag.
The source adapts `FeatureMessage::command()` with `VEYON_DECODE_COMMAND`.
Qt metadata exports are generated by AUTOMOC; Qt 6 uses the v2 query export.

## Build

Tools below are developer requirements only, not extra runtime prerequisites.

### Qt 5

Install Qt 5.12 with its MinGW g++ 7.3 toolchain and obtain Veyon 4.7.5 headers.
In PowerShell from the repository root:

```powershell
$env:PATH = "C:\Qt\Tools\mingw730_64\bin;$env:PATH"
cmake -S . -B build-qt5 -G "MinGW Makefiles" `
  -DCMAKE_CXX_COMPILER="C:/Qt/Tools/mingw730_64/bin/g++.exe" `
  -DCMAKE_MAKE_PROGRAM="C:/Qt/Tools/mingw730_64/bin/mingw32-make.exe" `
  -DVEYON_TARGET_VERSION=4.7.5 `
  -DVEYON_SOURCE_DIR="C:/src/veyon-4.7.5"
cmake --build build-qt5
```

Output: `build-qt5/internet-guard-qt5.dll`.

### Qt 6

Use Qt 6.7.2, a compatible MinGW toolchain and Veyon 4.9.0 headers.
If needed, a Qt developer installation can be obtained with aqtinstall:

```powershell
py -m pip install aqtinstall
py -m aqt install-qt windows desktop 6.7.2 win64_mingw --outputdir C:\Qt-aqt
py -m aqt install-tool windows desktop tools_mingw1310 --outputdir C:\Qt-aqt
git clone --depth 1 --branch v4.9.0 https://github.com/veyon/veyon.git ..\veyon-src-490
$mingw = "C:\Qt-aqt\Tools\mingw1310_64\bin"
$qt6 = "C:\Qt-aqt\6.7.2\mingw_64"
$env:PATH = "$mingw;$qt6\bin;$env:PATH"
cmake -S . -B build-qt6 -G "MinGW Makefiles" `
  -DWITH_QT6=ON `
  -DCMAKE_CXX_COMPILER="$mingw/g++.exe" `
  -DCMAKE_MAKE_PROGRAM="$mingw/mingw32-make.exe" `
  -DCMAKE_PREFIX_PATH="$qt6" `
  -DVEYON_SOURCE_DIR="..\veyon-src-490"
cmake --build build-qt6
```

Output: `build-qt6/internet-guard-qt6.dll`.
CMake selects the bundled core import library by Qt branch.
For another core, generate an import library from its matching `veyon-core.dll`
and point `VEYON_CORE_LIBRARY` and `VEYON_SOURCE_DIR` at matching inputs:

```powershell
gendef veyon-core.dll
dlltool -d veyon-core.def -l libveyon-core-qt6.dll.a -D veyon-core.dll
```

Important CMake options: `WITH_QT6`, `VEYON_TARGET_VERSION`,
`VEYON_SOURCE_DIR`, `VEYON_CORE_LIBRARY`. Their defaults are in CMakeLists.txt.

### Installer

After building both DLLs:

```powershell
pwsh -File installer\build-installer.ps1 `
  -PluginDllQt5 build-qt5\internet-guard-qt5.dll `
  -PluginDllQt6 build-qt6\internet-guard-qt6.dll
```

The self-contained Win32 installer embeds both variants, detects Qt, reads
the Veyon version, selects the destination and requests elevation when needed.
A version warning does not establish compatibility beyond the documented range.

## Verification and resources

Inspect DLL imports, Qt version tags and metadata exports before distribution.
On dedicated test PCs, install on Master and Server, restart both and verify
button visibility, selected targets, actual traffic and removal of owned rules.
`tools/fw_test.cpp` is a manual backend test: it modifies real firewall rules
when elevated. Do not run it on an operational system without authorization.
There is no automated unit-test suite for this plugin.

The runtime icon is the embedded PNG `network-offline.png`; the editable source
is `network-offline.svg`. Do not introduce a runtime dependency on Qt Svg.
When editing SVG, use explicit colors/opacity rather than unsupported fill syntax.
